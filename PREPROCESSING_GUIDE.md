# Component 4 preprocessing: what happens and why

Synthetic datasets still need a preprocessing and validation pipeline. They are not automatically correct because they were generated by software.

The active artifact is **v3.0, moderate-overlap synthetic PP1 demonstration**. `multimodal_fusion/preprocessing.py` implements a scikit-learn transformer, and `scenarios.py` saves the fitted transformer and Random Forest together in one pipeline. The API and command line use that saved pipeline for prediction.

## Score-level pipeline

`Input table → data-integrity checks → participant split → select [MPS,VPS,HPS] → numeric/range/missing checks → Random Forest → SHAP/LIME → report`

| Step | What is implemented |
|---|---|
| Dataset integrity | Require IDs, labels, provenance and the three score columns; reject missing/duplicate IDs, unknown labels and duplicate score vectors requiring a grouping decision. |
| Feature selection | Only motor_pd_probability, voice_pd_probability and handwriting_pd_probability are input features. Exclude the assigned label, synthetic ID, split, provenance, scenario and generator noise. |
| Column ordering | Always use MPS, VPS, HPS in that canonical order, even if a table supplies columns in another order. |
| Numeric checks | Convert valid numeric table values to floating point; reject boolean values and invalid numeric entries. The public API uses strict numeric fields. |
| Missing / invalid data | Reject NaN and infinity; reject scores outside [0,1]. No silent clipping or fabricated filling. A missing live score returns an incomplete assessment without a class prediction. |
| Splitting | Stratified 600/200/200 participant splits before fitting. The entire preprocessing/model pipeline is cloned inside each training CV fold. |
| Fitted state | The final transform is fitted on 600 training rows. Its recorded training ranges are audit information, not limits estimated from test data. |
| Scaling | No StandardScaler for Random Forest: inputs are already [0,1] scores. The logistic-regression comparison has its own training-only StandardScaler. |
| Target labels | Class strings are the supervised target. They are not additional input columns. The model's internal class order is explicitly mapped back to PD, ET, CA, AP, DLB. |
| Saving and serving | Save fitted preprocessor and model together; apply the same validation and ordering during training and inference. |

The simulator clips its generated probabilities to [.001,.999] as part of its documented data-generation design. This is separate from preprocessing incoming data; invalid user scores are rejected, not clipped.

## What belongs to Components 1–3

- Motor: sensor checks, filtering, segmentation and motor-feature extraction.
- Voice: audio decoding, recording-quality checks and acoustic-feature extraction.
- Handwriting: image preparation and handwriting-feature extraction.

Those components produce their own scores. Component 4 consumes the scores. The uploaded sensor/audio/image archives are not secretly passed through this synthetic fusion training flow.

## What to show in the viva

1. The dataset explorer: the label and metadata columns exist but are excluded from model features.
2. The preprocessing panel on the main screen and `/api/preprocessing`: saved steps and 600 training fit rows.
3. A valid three-score example: show the predicted profile and explanations.
4. A missing score: show `incomplete` instead of fabricated output.
5. An out-of-range value: show rejection through `/docs`.
6. Moderate test results and retained harder benchmark as separate scenarios.

The active moderate scenario uses 1,000 simulated participants, seed 1401, noise SD 0.50. A 500-record confirmation sample uses seed 1402. The original 1,000-record hard dataset, seed 401 and noise 0.85, remains unchanged. The higher moderate result reflects a different assumed scenario, not clinical validation or an improvement on the unchanged hard task.
